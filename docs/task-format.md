# 任务文件格式规范

lightty 任务数据的唯一持久化格式。`Sources/LighttyCore` 与将来的 shell hooks 都必须按本文读写。

## 位置与命名

- 目录：`~/.lightty/tasks/`
- 文件：`<净化后任务名>.md`，每个任务一个文件

### 文件名净化规则

从任务名（frontmatter 的 `name` 保留原文）派生文件名：

1. 删除所有 `/` 和 `:` 字符
2. 连续空白（空格、Tab 等）折叠为单个空格，去除首尾空白
3. 其余字符原样保留（含 CJK）
4. 净化结果为空时使用 `task`
5. 重名时在文件名后追加 `-2`、`-3`、……（取第一个不存在的）

示例：`修 a/b: 会话  管理` → `修 ab 会话 管理.md`

## 文件结构

```
---
name: 修会话管理方案
status: active
cwd: /Users/me/project/foo
tool: claude
created: 2026-08-22T10:00:00Z
updated: 2026-08-22T12:30:00Z
sessions:
  - claude:3551e356-5b15-43d1-86a5-69764b142807
---
（markdown 正文 = handoff 内容）
```

- 文件以 `---\n` 开头（首行），frontmatter 到下一个单独成行的 `---` 结束
- 正文 = 结束 `---` 行换行符之后的全部字节，读写时**字节原样保留**（包括结尾是否有换行符）
- 编码 UTF-8

## frontmatter 规则

严格子集，不是完整 YAML：

- 每个键一行，格式 `key: value`（冒号后恰好一个空格起值；值不加引号、不转义）
- `sessions` 是唯一允许的列表键：`sessions:` 独占一行，条目行固定为 `  - <tool>:<session-id>`（两个空格 + `- `，tool 与 id 用第一个 `:` 分隔，两侧非空）
- 条目行只允许紧跟在 `sessions:` 块内出现
- 键不允许重复
- 未知键：读取时保留原始行，写回时原样输出（向前兼容；未知键必须是单行键值，不允许是列表）

### 字段表

| 键 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `name` | 是 | 任意单行文本 | 任务名原文（未净化） |
| `status` | 是 | `active` \| `stuck` \| `done` | **已弃用**（仅兼容保留），见下节 |
| `cwd` | 是 | 绝对路径 | 任务工作目录 |
| `tool` | 否 | 工具名（如 `claude`） | 缺省时序列化不写该键 |
| `created` | 是 | ISO8601 UTC，如 `2026-08-22T10:00:00Z` | 创建时间 |
| `updated` | 是 | ISO8601 UTC | 最后修改时间；每次写入必须刷新 |
| `sessions` | 否 | 列表，条目 `<tool>:<session-id>` | 关联会话，追加时去重（tool+id 相同视为重复） |

### status：已弃用（2026-08-30）

`status` 保留在格式里仅为兼容既有文件与解析器校验：解析照旧、建档固定写
`active`、任何一方都不再更新或读取其语义。弃用理由：

- 实时的活跃/休眠由 UI 按「有无 pane 绑定」派生，不需要落盘；
- 接手的 agent 读的是正文（「下一步」「卡点与风险」），status 对它是冗余压缩;
- 给人看的分诊细节走任务行单击气泡里的 handoff 摘要（一次点击可见原文），
  列表层的一词后缀是它的有损复读，且天然滞后、易撒谎。

若将来任务量大到列表需要不点击即可分诊，再重新赋予语义——届时按真实需求
定义，而不是先造字段再找用途。

### 序列化顺序

写文件时已知键按固定顺序输出：`name`、`status`、`cwd`、`tool`（有值时）、`created`、`updated`、未知键原始行（按读取顺序）、`sessions`（非空时）。

### 错误处理

格式非法必须报错（带 1-based 行号），禁止静默容错。非法情形包括：

- 文件不以 `---\n` 开头 / frontmatter 未用 `---` 行闭合
- 无 `:` 或冒号后无 ` ` 的行；键重复
- `status` 不在枚举内；`created`/`updated` 不是 ISO8601
- `sessions:` 块外出现 `  - ` 条目行；条目缺 `:` 分隔

批量列出任务时，单个非法文件只从结果中剔除并记入失败清单，不得中断整个列表。

## 原子写约定

所有写入（创建、修改、重命名）遵循：

1. 在**同一目录**下写临时文件（`.`开头、`.tmp` 结尾，不会被任务扫描匹配到）
2. `rename(2)` 到目标路径（同文件系统内原子替换）
3. rename 失败时删除临时文件并报错

读方任何时刻只会看到完整的旧内容或完整的新内容。shell hooks 修改任务文件时必须同样走"临时文件 + mv"，禁止原地追加或截断写。

## 正文规范（handoff 内容）

正文即任务的 handoff 文档，原则采纳自 mattpocock 的 handoff skill（详见 HANDOVER.md 第 8.3 节）：为接手的 agent 写、引用不复制（commit/路径/URL 指向已有产物）、脱敏（key/密码/PII 不落盘）、面向下一步裁剪。

覆盖式快照按以下结构重写正文；人工里程碑另起日期段追加，不被快照覆盖。
节头为英文（协议语言，2026-08-30 起；此前的中文节头由摘要解析兼容，旧文件无需迁移）：

```
## Next steps                    ← 接手 agent 读的第一句话
## Current state
## Key decisions & constraints   ← 引用式：commit/文件路径/文档链接
## Blockers & risks
## Suggested commands & skills
```
