# 用户数据与格式升级

lightty 自有持久数据独立于应用包、安装路径、构建目录和版本。默认根目录为 `~/.lightty/`；测试使用隔离临时目录。

| 文件 | 所有权与内容 | `format` / `version` |
| --- | --- | --- |
| `preferences.json` | 外观、语言、重点色、主题开关、Agent 选择与启动命令、菜单栏开关、侧栏偏好、任务排序、引导提示状态 | `lightty.preferences` / `1` |
| `workspace.json` | 窗口、标签页、分屏树及可恢复终端信息；不是运行进程备份 | `lightty.workspace` / `1` |
| `organization.json` | 跨 Agent 项目、会话归属、排序、折叠及本地归档；不是对话正文或目录缓存 | `lightty.organization` / `1` |
| `tasks/*.md`、`tasks/archive/*.md` | **已发布**的 Handoff 文档及其归档 | 原有 Markdown/frontmatter，见 task-format.md；不参与 JSON 迁移 |

前三种 JSON 以首次发布的 v1 定稿，文件类型与格式版本必须匹配；应用版本与文件格式版本独立。

终端、Agent 会话和 Handoff 文件的关联、恢复与导航不变量见 [终端关联契约](terminal-associations.md)。工作区只保存关联和恢复意图，不保存 hook 活动态，也不将“尚无 hook”视为会话已结束。

## 偏好文件

```json
{
  "format": "lightty.preferences",
  "version": 1,
  "values": {
    "lightty.appearance": "system",
    "lightty.agent.selected": "codex"
  }
}
```

- 键按 lightty 设置领域命名。未设置的键使用代码默认值，不能把缺省误判成损坏。
- `values` 与顶层未知字段在写回时保留；不要求未来新增字段被旧代码理解。
- 新安装创建当前格式空偏好，使用代码默认值。正常读写不再从 UserDefaults 导入或回填旧设置；测试可注入独立的偏好存储。
- 偏好修改立即更新内存，后台串行队列按 50ms 窗口合并字段变更；落盘在进程间文件锁下重读并合并磁盘数据，原子替换。失败保留待写变更并提示，下次修改或显式 `flush()` 重试；正常退出前 `flush()` 等待落盘。异常强退可能丢失尚未落盘的变更。配置权限为 `0600`，新建目录权限为 `0700`。锁文件不是用户设置。
- 损坏、不可读或未来版本不会按空配置重建；界面提示错误，原文件保留。配置中不应存放凭据，Agent 登录仍由各工具管理。

## 首次启动自动升级

启动顺序：**检查/转换/校验 → 备份与写回 → 读取偏好 → 恢复工作区 → 打开终端**。入口在 `main.swift`，先于 FilePreferences、AppDelegate、Ghostty 运行时和项目库初始化。

- 每次启动检查三个 JSON；当前格式直接使用，后续启动不重复转换、不生成多余备份、不改写文件时间。
- 所有文件预检通过后才开始写入。需要升级但有其他 lightty 实例时，要求先退出旧实例，避免覆盖它尚未保存的现场。迁移进程之间使用 `.migration.lock` 互斥。
- 升级前原文件逐字节备份到 `backups/migration-<UUID>/`；备份和输出文件权限 `0600`。每个文件原子替换，不宣称多文件事务；中断后重新启动可继续，全部成功前不初始化应用业务。
- 缺失文件视为新安装/未使用；损坏文件、错误类型、未来版本、低于最低支持版本、转换链缺失或校验失败阻止启动，提示原因，保留原文件或升级前备份。不能按空数据继续覆盖。
- 开发期无 `format` 的 v1 偏好及 `session.json`、`session-library.json` 由引导转换导入当前格式。成功后旧命名文件移出活动目录，其原始内容保留在备份；新旧文件冲突不会自动择一覆盖。
- 用户不需要运行命令。开发诊断可使用 `lightty --migrate-data`，调用同一启动入口但不打开 GUI/终端。

## 迁移 Module 与迭代规则

| Module | 职责 |
| --- | --- |
| `PersistenceFormat` | 三类文件的名称、类型标识与当前格式版本 |
| `JSONSchemaMigration` | 纯内存逐版本转换；`steps[N]` 表示 `N → N+1`，无磁盘或 UI 操作 |
| `UserDataSchemas` | 按文件类型登记最低支持版本、转换步骤及当前 payload 校验 |
| `UserDataMigration` | 启动预检、引导转换、互斥、备份、原子替换及中断重试 |
| `FilePreferences` / `WorkspaceStore` / `SessionLibrary` | 正常业务读写，只处理当前格式 |

1. 已发布格式的破坏性字段修改必须提升对应文件的版本，在 `UserDataSchemas` 登记转换步骤；未发布功能直接定稿首版格式，不为开发过程中的调整添加版本链或迁移。
2. 发布新版本时，迁移链必须覆盖最低支持版本至当前版本；逐版本转换后按当前模型校验，所有步骤完成后才写盘。移除旧步骤必须同步提升最低支持版本，不能截断仍受支持的链。
3. 当前正式基线只有 v1，不编造历史版本；开发引导转换与正式版本链分开管理。迁移中的旧字段知识不得散入当前模型或 UI。
4. 同版本可选字段扩展必须定义缺省含义并测试。偏好未知字段往返保留；工作区和组织数据使用 typed Codable，不承诺未知字段无损往返，需要跨版本保留的新语义应升版本。
5. 测试使用隔离文件，覆盖首次转换、二次启动不变、链式转换、坏文件与未来版本保护、冲突与中断重试；不使用用户真实历史作为 fixture。
6. Handoff 是独立的已发布协议，路径、frontmatter、正文和 `cwd` 读取兼容不因 JSON 定稿而改变。

正常替换 `.app` 不涉及此目录。手动删除用户数据或清理软件仍可能删除它；归档也不是备份。Claude/Codex 的历史、认证和 hooks 配置、Ghostty 的共享配置保持各自工具的原有路径，不复制进 lightty 数据目录。
