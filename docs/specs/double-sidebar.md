# Spec：双层侧栏（工作区列 + 任务列）

状态：**已定稿，未实现**（2026-08-31 讨论定案，落文档待做）。
词汇约定同仓库：窗口 › 工作区（tab）› pane；任务 = handoff md 文件；
活跃/休眠 = UI 派生态（有无 pane 绑定）。

## Problem Statement

工作区目前是主区顶部的横向 tab 条，任务是侧栏纵向列表。工作区一多，
横向 tab 挤成一排难以辨认和管理；而任务列表已经证明纵向是更好的形态。
若把工作区也塞进现有单条侧栏（双区方案），两个都可能很长的列表互相挤压，
信息更拥挤——被否决。

## Solution

Ulysses / Mail 式三栏范式：**工作区列（~180pt）｜任务列（~270pt）｜终端主区**。
两个列表各占一整列高度互不挤压；横向 tab 条整体移除。左列回答"我在哪"
（导航，粗粒度靠外），右列回答"有什么"（资料库）。两列是并列而非钻取
（任务是全局的，不按工作区过滤），但骨架天然支持将来做"按工作区过滤任务"。

## User Stories

1. 作为用户，我想在侧栏纵向看到当前窗口的全部工作区，这样工作区多时也能一眼分辨。
2. 作为用户，我想单击工作区行切换工作区，这样导航和管理在同一处。
3. 作为用户，我想看到当前工作区行高亮，这样随时知道自己在哪。
4. 作为用户，我想在工作区行看到「N panes」副标题，这样不切换就能了解每个工作区的规模。
5. 作为用户，我想双击工作区行重命名（沿用 NameEditorPopover），这样命名习惯与旧 tab 双击一致。
6. 作为用户，我想通过工作区行的 ⋯ 菜单（ShellMenuPopover）重命名/关闭工作区，这样管理动作有统一入口。
7. 作为用户，我想在工作区列有 ➕ 新建工作区，这样不必去标题栏。
8. 作为用户，我想工作区多于可视高度时列内可滚动，这样数量不设限。
9. 作为用户，我想任务列的一切交互保持原样（单击目的地气泡、双击快跳、⋯ 管理、节标签 + 搜索/建档按钮），这样已有习惯不被破坏。
10. 作为用户，我想 hover 预览和钉住两种侧栏形态都显示完整双列，这样预览时也能切工作区。
11. 作为用户，我想横向 tab 条消失后仍能用 ⌘1..9 切换工作区（core keybind 既有能力），这样键盘流不受影响。
12. 作为用户，我想侧栏收起时标题栏常显当前工作区名，并点击弹出快速切换菜单，这样不开侧栏也有轻量通道。
13. 作为用户，我想关闭工作区遵循既有语义（最后一个工作区关窗口；含绑定 pane 时侧栏活跃态即时回退），这样行为可预期。
14. 作为用户，我想拖拽 pane 到别的工作区的能力不受影响（后续可探索拖到工作区行），这样布局自由度不倒退。
15. 作为用户，我想两列宽度是 ShellStyle token，这样后续打磨改一处生效。
16. 作为用户，我想双列沿用 chrome 行高模数（28/12/10/内容左轴 20）与侧栏底色，这样视觉体系不分裂。
17. 作为深色模式用户，我想双列完整跟随明暗外观，这样与既有壳层一致。
18. 作为用户，我想工作区列表在新建/关闭/重命名/切换后即时刷新，这样侧栏永远反映真实状态。

## Implementation Decisions

- **列序**：工作区列在最左（三栏范式：越左越粗粒度导航），任务列居中，终端主区右侧。
- **横向 TabStripView 整体移除**，包括其高度参与的主区布局；`refreshTabStrip`
  的职责由工作区列刷新 + 标题栏工作区标签接替。
- **标题栏工作区名标签升级**：从"仅单工作区显示"改为常显当前工作区名；
  单击从重命名改为弹快速切换菜单（ShellMenuPopover：各工作区 + 勾选当前，
  重命名入口移入菜单或保留于侧栏行双击）。
- **标题栏"新工作区"按钮保留**（侧栏收起时的快捷通道），与工作区列 ➕ 并存。
- **抽屉开合模型第一期不变**：单开关，hover 预览 / 钉住均整体显示双列
  （总宽 ~450pt）；Ulysses 式分级折叠（只留任务列）为第二期。
- **工作区行数据源**：TerminalWindowController 的 tabs/activeTabIndex
  （per-window），复用既有 addTab/selectTab/closeTab/renameTab/workspaceName
  入口，不新造状态；刷新走既有中心点（原 refreshTabStrip 调用位）。
- **宽度 token**：ShellStyle 增加工作区列/任务列宽度常量，替换现有单一 sidebarWidth。
- **样式**：行样式对齐任务行（hover/选中 fill、圆点/副标题排版），节标签行
  「工作区」+ ➕ 沿用「任务」节标签体系。
- 侧栏动画（逐帧重排 + prompt-clear 抑制）针对总宽调整常量即可，机制不变。

## Testing Decisions

- 本仓约定：AppKit UI 层无单元测试，纯逻辑在 LighttyCore 测试
  （TaskStore/TaskFile/FuzzyMatch 为先例）。本特性为纯 UI 编排，
  不新增 LighttyCore 逻辑，**不新增单测**；好的测试只测外部行为，
  为测试而抽 view-model 层被认为是为覆盖率发明缝隙，不做。
- 验收走人工冒烟清单：多工作区创建/切换/重命名/关闭、⌘1..9、
  标题栏快速切换、hover 预览与钉住双形态、明暗外观、侧栏动画无闪烁
  （kernel prompt-clear 路径回归）、打包形态（scripts/package-app.sh）复测。

## Out of Scope

- 工作区行展开露出 pane 的树式活地图（cmux 式，第二期）。
- 按工作区过滤任务列（骨架支持，暂不做）。
- Ulysses 式分级折叠（只留任务列的中间态）。
- 拖拽 pane 到工作区行进行跨工作区移动。
- 跨窗口的工作区聚合视图（工作区严格 per-window）。

## Further Notes

- 讨论中已否决的备选：单侧栏双区（VS Code OPEN EDITORS 式，信息拥挤）、
  Slack/Discord 图标 rail（工作区短命无图标，chrome 过重）、Arc 全套
  Spaces（过重，仅取"纵向优于横向"结论）。
- 工作区默认名为全局计数（「工作区 N」跨窗口唯一），双击改名不落盘——
  该命名模型不因本特性改变。
