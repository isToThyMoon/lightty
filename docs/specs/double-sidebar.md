# Spec：双层侧栏（标签页列 + 任务列）

状态：**已定稿，未实现**（2026-08-31 讨论定案，落文档待做）。
词汇约定同仓库：窗口 › 标签页（tab）› pane；任务 = handoff md 文件；
活跃/休眠 = UI 派生态（有无 pane 绑定）。

## Problem Statement

标签页目前是主区顶部的横向 tab 条，任务是侧栏纵向列表。标签页一多，
横向 tab 挤成一排难以辨认和管理；而任务列表已经证明纵向是更好的形态。
若把标签页也塞进现有单条侧栏（双区方案），两个都可能很长的列表互相挤压，
信息更拥挤——被否决。

## Solution

Ulysses / Mail 式三栏范式：**标签页列（~180pt）｜任务列（~270pt）｜终端主区**。
两个列表各占一整列高度互不挤压；横向 tab 条整体移除。左列回答"我在哪"
（导航，粗粒度靠外），右列回答"有什么"（资料库）。两列是并列而非钻取
（任务是全局的，不按标签页过滤），但骨架天然支持将来做"按标签页过滤任务"。

标签页列是**两级树（cmux 形态）**：标签页行 = 容器，pane 行 = 叶子——
pane 的导航与管理由此落位（此前无处安放的缺口）。标签页默认展开，可通过
disclosure chevron 折叠；折叠只影响导航显示，不改变标签页/pane 状态。
整列即当前窗口的活地图，直指产品初衷"掌握任务对应的标签页、pane 状态"。

## User Stories

1. 作为用户，我想在侧栏纵向看到当前窗口的全部标签页，这样标签页多时也能一眼分辨。
2. 作为用户，我想单击未激活的标签页行先切换过去，再次单击已激活行时折叠或展开
   其 panes，这样导航和层级管理共用整行的大命中区。
3. 作为用户，我想看到当前标签页行高亮，这样随时知道自己在哪。
4. 作为用户，我想在标签页行看到「N panes」副标题，这样不切换就能了解每个标签页的规模。
5. 作为用户，我想双击标签页行重命名（沿用 NameEditorPopover），这样命名习惯与旧 tab 双击一致。
6. 作为用户，我想通过标签页行的 ⋯ 菜单（ShellMenuPopover）重命名标签页，并用
   hover 行尾的独立 ✕ 关闭，避免菜单与行尾出现重复关闭入口。
7. 作为用户，我想在标签页列标题行集中使用向右分屏、向下分屏与新建标签页，
   这样窗口级操作不占据 terminal 上方空间。
8. 作为用户，我想标签页多于可视高度时列内可滚动，这样数量不设限。
9. 作为用户，我想任务列的一切交互保持原样（单击目的地气泡、双击快跳、⋯ 管理、节标签 + 搜索/建档按钮），这样已有习惯不被破坏。
10. 作为用户，我想 hover 预览和钉住两种侧栏形态都显示完整双列，这样预览时也能切标签页。
11. 作为用户，我想横向 tab 条消失后仍能用 ⌘1..9 切换标签页（core keybind 既有能力），这样键盘流不受影响。
12. 作为用户，我想原生标题栏不重复显示标签页名，避免与侧栏行和 pane header
    重复，并把顶部空间完整留给窗口拖拽与 terminal。
13. 作为用户，我想关闭标签页遵循既有语义（最后一个标签页关窗口；含绑定 pane 时侧栏活跃态即时回退），这样行为可预期。
14. 作为用户，我想拖拽 pane 到别的标签页的能力不受影响（后续可探索拖到标签页行），这样布局自由度不倒退。
15. 作为用户，我想两列宽度是 ShellStyle token，这样后续打磨改一处生效。
16. 作为用户，我想双列沿用 chrome 行高模数（28/12/10/内容左轴 20）与侧栏底色，这样视觉体系不分裂。
17. 作为深色模式用户，我想双列完整跟随明暗外观，这样与既有壳层一致。
18. 作为用户，我想标签页列表在新建/关闭/重命名/切换后即时刷新，这样侧栏永远反映真实状态。
19. 作为用户，我想每个标签页行下方纵向列出其全部 pane，并能从标签页行折叠/展开，这样既能看到窗口活地图，也能收起暂时不关心的标签页。
20. 作为用户，我想 pane 行用两行显示绑定态圆点、pane 名、活动状态、绑定任务名和当前目录，这样"任务 ↔ 现场"及所处项目不用跳去别处比对。
21. 作为用户，我想单击 pane 行即切到其所在标签页并聚焦该 pane，且当前 pane 行保持 hover 同款高亮，这样跨标签页定位一步到达并能明确看到落点。
22. 作为用户，我想 hover pane 行出现 ✕ 关闭（与 pane 胶囊 ✕ 同一内核关闭通路），这样清理会话不必先切换过去。
23. 作为用户，我想 pane 行随 pane 新建/关闭/改名/绑定变化即时刷新，这样活地图不撒谎。
24. 作为用户，我想 pane 重命名仍只在灵动岛进行（pane 行不提供编辑），这样编辑入口唯一、不产生两处状态。
25. 作为用户，我想过长的 pane 当前目录优先保留路径末尾，并可通过 tooltip 查看完整路径，这样窄侧栏中仍能辨认具体项目目录。

## Implementation Decisions

- **列序**：标签页列在最左（三栏范式：越左越粗粒度导航），任务列居中，终端主区右侧。
- **横向 TabStripView 整体移除**，包括其高度参与的主区布局；标签页导航、当前态
  与重命名统一由标签页列承接。标题栏不再重复显示标签页名。
- **顶部职权（2026-09-02 改）**：向右分屏、向下分屏、新标签页三键从原生标题栏
  迁入标签页列标题行；原生标题栏只保留红黄绿与侧栏开关。窗口使用
  `fullSizeContentView`，标签页列避让原生标题栏，terminal 主区则上下铺满窗口边界。
  pane header 身份胶囊按各 pane 水平居中；标签页列收起后也不会落到左上系统操作区
  下方，窄 pane 仍沿用任务 hint 隐藏与标题截断规则。灵动岛以胶囊中点和顶边为
  形变锚：向左右等量、向下展开，第一行状态 icon 与标题全程保持原位；收起沿同一
  路径反向执行。
- **抽屉开合模型第一期不变**：单开关，hover 预览 / 钉住均整体显示双列
  （总宽 ~450pt）；Ulysses 式分级折叠（只留任务列）为第二期。
- **开合职权（2026-09-02 改）**：标题栏侧栏按钮 = 标签页侧栏开关，task 卡片开着时
  点击为全关（两块一组动画同收）。task 卡片由边缘钮控制：卡片关着时窗口左缘中点
  展开钮、开着时卡片右缘关闭钮——两态纵向均锚定整窗边界中线，卡片只提供关闭钮
  的横向吸附位置。同形镜像的贴边半胶囊宽 12，与侧栏两侧 12 的边沟等宽。标签页
  侧栏不再有自己的边缘钮，右边线负责调宽与越界左拖关闭。
- **标签页行数据源**：TerminalWindowController 的 tabs/activeTabIndex
  （per-window），复用既有 addTab/selectTab/closeTab/renameTab/tabName
  入口，不新造状态；刷新走既有中心点（原 refreshTabStrip 调用位）。
  整行单击按当前态分流：未激活 → `selectTab`，已激活 → 切换该标签页折叠态；
  disclosure 不受激活态限制，始终直接切换折叠态。
- **宽度 token**：ShellStyle 增加标签页列/任务列宽度常量，替换现有单一 sidebarWidth。
  标签页列以 token（200pt）为最小宽度，右边线可连续拖到最大 2 倍；到达最小值后
  继续向左拖过防误触阈值则关闭。用户调整后的宽度写入偏好，当前窗口按钮开合保留，
  后续新窗口沿用。
- **样式**：行样式对齐任务行（hover/选中 fill、圆点/副标题排版），节标签行
  「标签页」+ 分屏/新建三键沿用壳层图标按钮体系。
- **pane 树**：标签页行下嵌套 pane 行（缩进一级），数据源 = 该标签页的
  pane 树叶子序；tab UUID 作为折叠键，折叠状态仅保存在侧栏实例中。
  pane 行第一行显示 pane 名 + 行尾完整状态文字；pane 名占弹性空间并在过长时尾部
  截断，状态文字为 hover 关闭按钮预留固定槽位、不随按钮出现而横跳。第二行从 pane
  内容左轴顶左显示任务名 + cwd；cwd 走
  Ghostty PWD action（OSC 7/9/1337），从头截断并保留完整路径 tooltip。
  pane 行圆点/任务名复用 pane header 胶囊的既有派生，关闭走
  requestCloseFromUser 同一通路；标签页行的「N panes」副标题因树已可见而移除。
- 侧栏动画（逐帧重排 + prompt-clear 抑制）针对总宽调整常量即可，机制不变。

## Testing Decisions

- 本仓约定：AppKit 事件循环与约束编排不造测试缝隙；宽度上下限、关闭阈值和偏好
  round-trip 是独立纯规则，由 `TabSidebarWidthTests` 覆盖。
- 验收走人工冒烟清单：多标签页创建/切换/折叠/重命名/关闭、cwd 实时更新与
  路径头部截断、⌘1..9、
  标题栏快速切换、hover 预览与钉住双形态、明暗外观、侧栏动画无闪烁
  （kernel prompt-clear 路径回归）、打包形态（scripts/package-app.sh）复测。

## Out of Scope

- 按标签页过滤任务列（骨架支持，暂不做）。
- Ulysses 式分级折叠（只留任务列的中间态）。
- 拖拽 pane 到标签页行进行跨标签页移动。
- 跨窗口的标签页聚合视图（标签页严格 per-window）。

## Further Notes

- 讨论中已否决的备选：单侧栏双区（VS Code OPEN EDITORS 式，信息拥挤）、
  Slack/Discord 图标 rail（标签页短命无图标，chrome 过重）、Arc 全套
  Spaces（过重，仅取"纵向优于横向"结论）。
- 标签页默认名为全局计数（「标签页 N」跨窗口唯一），双击改名不落盘——
  该命名模型不因本特性改变。
