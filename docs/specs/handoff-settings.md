# Handoff 设置页

## 目标与边界

把交接文档从「只能在侧栏里一条条点开」变成一个可浏览的文档库：进行中的、已归档的，
以及 lightty 替用户对 Agent 说的那套协议，合成一页。

lightty 只读这些文件并调用 `TaskStore` 已有的归档 / 恢复 / 永久删除，不改写正文、
不改 frontmatter、不碰 CLI 会话。协议一栏**只展示**，这一版不放开自定义。

## 布局

从 Settings 的 Handoff 标签进入，**保留原有设置导航**，三栏骨架复用
`ColumnBrowserView`（与 Skills、Plugins 同一具）。

```text
┌──────────────┬──────────────┬────────────────────┬─────────────────────────┐
│ 返回应用      │ 进行中      8 │ 进行中        8 ↻  │ 改写启动浮层             │
│ 搜索设置      │ 已归档      3 │ 搜索 Handoff 文档…  │ 2 小时前 · 接上 TaskStore │
│              │ 协议         │                    │                         │
│ 通用          │              │ 改写启动浮层        │ 打开文件  Finder  归档   │
│ 外观          │              │ 2 小时前 · 接上…    │ /Users/…/tasks/xxx.md   │
│ Handoff ●    │              │                    │ ─────────────────────── │
│ Skills       │              │ 侧栏回弹           │ ---                     │
│ 归档          │              │ 昨天 · 用原生基线… │ name: 改写启动浮层        │
│              │              │                    │ ---                     │
│              │              │                    │ ## Next steps           │
│              │              │                    │ 正文，可选择和滚动        │
└──────────────┴──────────────┴────────────────────┴─────────────────────────┘
```

- 左栏固定三行，数量取自 store 的实时扫描；「协议」不显示数量（它不是一批文档）。
- 选中「协议」时中栏是空的，**这是本来的样子**，不是「没找到」。中栏的空态文案
  为此单独一条，右栏那句「选一份文档」在协议栏下取空串，不出现。
- 搜索只作用于当前分类，比对任务名、下一步摘要与文件名。
- 列宽、拖动与持久化由骨架负责，键前缀 `settings.handoff`，与 Skills 各存各的。
- 外部改动（Agent 重写文档、Finder 里删文件）由中栏表头的 ↻ 重扫。本页**不订阅**
  任务目录监听：它不是常驻视图，订阅换来的是一条只在设置页打开时才有意义的通知路径，
  而页面上自己做的动作本来就当场重读。

### 中栏第二行显示什么

**最近更新时间 + `## Next steps` 的第一行。**

两样各答一个问题，缺一个都不够挑：时间答「这份还新鲜吗」，下一步答「这份是干什么的」。
任务名往往是一句项目名，一屏里好几个长得差不多，光有名字选不动。

下一步取自 `LaunchComposer.summarize`，**不另写解析器**：任务气泡里显示的「下一步」
就是它认出来的那一节，两处认的必须是同一段，否则用户在两个地方读到的是同一份文档
的两个说法。认不出摘要时只显示时间，不显示「暂无摘要」占位。

### 右栏

文档：任务名、同一行副标题、动作按钮、**完整实际路径**（可选中、独立滚动、不截断）、
分隔线，然后是 `SkillDocumentPresentation` 渲染的正文。

正文是**磁盘上的全文**，含 frontmatter：右栏自陈的是「这个文件里有什么」，把
frontmatter 藏起来就跟用户用编辑器打开看到的东西对不上。frontmatter 由
`SkillDocumentPresentation` 以等宽底色单独成块，与正文分得开。

动作：打开文件、Finder 定位；进行中多一个「归档任务」，已归档多「恢复」与
「永久删除…」。永久删除沿用原归档页的确认框文案与按钮顺序——用户已经认得那个框，
换说法只会让它看起来像一件新的、没见过的事。**任何一个动作都不碰 CLI 会话。**

协议：五块，与原 Handoff 页逐块相同——开场注入、中途绑定注入、技能调用写法、
插件没装时的直述兜底、注入时机。整栏可滚动。

## 决定

### 正文只读

不做可编辑。这些文件 **Agent 也在写**（交接协议要求它「同目录点开头临时文件 + mv」
原子替换），设置页要是也能编辑，就得处理两边同时改的冲突，而冲突处理不在这一版的
范围里。要改就打开文件，交给系统默认应用——那条路上的冲突由编辑器自己负责。

### 协议文本只有一份

页面上的协议文字全部当场取自 `HandoffProtocol`，**不另存副本**。副本迟早跟真正注入的
对不上，而「用户照着设置页读、Agent 收到的却是别的」是最难被发现的一种不一致。
`HandoffProtocol` 的文档注释里那张「四处取用点」的清单包含这一页，新增取用点必须写进去。

协议原文**不走本地化**：它是跨会话的数据格式协议，固定英文（同
`Sources/lightty/Localization.swift` 的边界说明）。这一栏的标题与说明文字走本地化。

「技能还没装」那句是**查出来的**（`HookInstaller.handoffSkillAvailable`），不是断言。
技能没装时敲下去是静默失败（两家都不报错），在这点上写一句「已随插件安装」等于骗人。
切到协议栏时重查一次，不拿构造时的旧结论。

### 归档走 TaskBindings，恢复与删除走 TaskStore

归档要把绑着这份任务的终端**全部解绑**，那是 `TaskBindings.archiveTask` 的职责；
绕过去直接调 `TaskStore.archive` 会留下指向 `archive/` 里某个文件的终端。
归档过的文件不可能有终端绑着，所以恢复与永久删除直接走 `TaskStore`。

动作做完自己立刻重读两栏，不等目录监听：用户按下按钮，列表就该是新的。

### 读不出来的文件也进列表

解析失败的 `.md` 用文件名当标题、错误当第二行，照常列出。一个坏掉的交接文档比一个
消失的交接文档好找。归档目录同理。

### 排序

最近更新在前。读不出时间的（解析失败）排最后按文件名——它们没有可比的时间，混在
中间会显得列表的序是随机的。这一页不提供手动排序：手动序是侧栏那张列表的东西
（`TaskManualOrder`），设置页是个浏览器，不是工作台。

## 数据依据

- 进行中 = `TaskStore.list()`（只扫任务目录顶层，忽略点开头文件）。
- 已归档 = `TaskStore.archivedFiles()`（拒绝软链接与目录外的路径）。
- 正文按 UTF-8 整文件读出；读不出时正文为空，文件仍在列表里。
- 不硬编码用户账号或本机绝对路径；测试一律用临时目录，不碰真实 `~/.lightty/tasks/`。

## 与「归档」设置页的关系

恢复与永久删除的行为整体搬到本页。原「归档」页（`ArchivedTasksView`）在
`SettingsView` 里的挂载点由接线方一并摘除，本页不动 `SettingsView.Page` 枚举。

## 测试

`Tests/LighttyTests/HandoffSettingsViewTests.swift`，全部走临时目录，视图直接立起来、
不经 `SettingsView`。守住的不变量：

- 两栏的内容都是从 store 读出来的；归档一份，两边的数量同时变。
- 选中一份文档，右栏给出磁盘全文与完整路径，且不可编辑。
- 归档 / 恢复 / 永久删除都落到磁盘并当场重读两栏；确认框答「取消」就什么都不做。
- 协议栏的文字用 `HandoffProtocol` **当场算出来的整段**去比对，不比对页面上抄下来的
  字面量——协议一改，页面没跟上就是这条测试挂。中栏同时必须是空的。
- 文件在眼皮底下消失时，右栏不留上一份的正文与路径。
