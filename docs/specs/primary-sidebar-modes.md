日期：2026-09-07。状态：**开发中，尚未达到发布验收**。
来源依据：[会话来源调研](session-provider-research.md)。术语见 [CONTEXT.md](../../CONTEXT.md)。

已实现：双模式外壳、Codex CLI 与 Claude 官方 SDK 的分页目录、原生命令计划、项目及手动归属持久化；设置的 Handoff 归档恢复/彻底删除；搜索与任务弹窗共用 Agent 启动组件。
待完成：helper 最终分发验收、规模与多版本 UI 验收、专用真实会话的恢复确认。官方 SDK + Node 22 的隔离技术验证与 Swift Adapter 两页读取已通过，证据和包体/性能见 [SDK helper 验证](claude-sdk-distribution-research.md)。下文未通过的验收门槛不代表现有能力。

当前目录每个来源分区先取 100 条；“加载更多”按需读取后续页，搜索明确只覆盖已加载记录。刷新按钮在加载期间变为取消。刷新与取消递增 generation，旧请求无法覆盖新状态；分页去重、循环游标检查、失败保留已有记录，完整来源读取成功后才清理失效记录。

### Sessions 项目与本地归档契约

- Project 是 lightty 的组织能力，可混合 Claude Code 与 Codex CLI 会话。「移到项目」只改变归属，不合并上下文，不移动 Agent 文件。
- Sessions 的「归档」筛选展示 lightty 自己归档的项目和会话，统一适用于两种 Agent；切换筛选不查询或修改 Agent。
- 单独归档会话保留其项目归属。项目菜单不提供归档操作；已有归档项目仍可恢复，恢复保留分组及成员单独设置的归档状态。
- 从归档项目中单独取回会话使用「恢复到最近会话」，显式移出该项目，避免恢复后仍被项目隐藏。移到其他可见项目、普通移出项目不隐式恢复会话。
- 删除项目只移除分组：继承项目归档的会话回到最近会话，单独归档的会话保持归档。此操作不删除对话或原始文件。
- 本地归档项目 ID 与会话 key 保存在组织数据中；旧文件缺少归档字段时按未归档读取。原始会话若被 Agent 清理，lightty 的归属引用不构成备份。
- Codex 原生 active/archived 分区都可作为发现来源，原生状态标为 `sourceArchived`，不映射成 lightty 归档；Claude 是否有原生归档接口不影响本地组织。

### Handoff 归档与搜索契约

- 首次成功归档提示“设置 → 归档”可恢复或彻底删除；失败不消耗首次提示。
- 设置 → 归档只管理 `tasks/archive/*.md`，恢复重名时保留两份，彻底删除需要二次确认；不写入 CLI 历史。
- 搜索右侧保留正文滚动预览，嵌入 `RestorePopoverController` 的共享 Agent、已打开位置、目的地和启动按钮。默认新标签页；回车优先前往已打开位置，否则执行当前 Agent/目的地选择。
- 搜索启动区独立滚动，最多占预览区 70%，长正文或多个已打开位置不覆盖控件。

## 1. 结论与范围

可行。复用 Agent 原生会话恢复，不在 lightty 重建对话引擎。
难点不是执行 resume，而是可靠发现会话、处理版本差异、正确归组以及区分“历史记录”和“当前运行现场”。

- 第一侧栏提供两种资料导航：Handoff 任务 / Sessions 会话；默认保留 Handoff 模式，升级不改变已有用户习惯。
- 第二侧栏继续展示当前窗口的标签页与终端，模式切换不新建、关闭或重排现场。
- 两模式共用第一侧栏的外壳，不把 Handoff 文档伪装成会话，也不把历史会话灌进 TaskStore。
- 会话首次单击默认在新标签页的新终端中恢复；已经在 lightty 打开的会话优先前往。
- 会话由原 Agent 恢复，不能将 Claude 会话的恢复工具切成 Codex。Handoff 模式仍可自由选择 Agent。
- 原始会话由 Agent 持有；lightty 只持有组织信息及可重建的列表缓存。

本文 Codex 明确指 **Codex CLI**，Claude Code 指其 CLI；不是 ChatGPT App 内的 Codex。本方案只读取 CLI 的本地历史，恢复仍运行 CLI。
“全部”的首期定义：本机已配置 CLI 来源下、跨工作目录的用户主会话。Codex 显式限定 `sourceKinds: ["cli"]`，不默认纳入 `vscode`、`appServer`、`exec` 或子 Agent；原生归档分区也作为只读发现来源，不决定 lightty 的归档筛选。
若某版本对 CLI 来源编码不同，先做 fixture/真实专用会话验证并更新 Adapter，不靠放开所有来源掩盖兼容性问题。
不承诺远程机器、云端独有会话、其他系统用户、已删除或未落盘的会话。目录扫描结果不等于用户账号的全球历史。

## 2. UI 与行为

### 2.1 模式标题

- 将现有 11.5pt、浅色的“任务”小节标签改为可点击标题按钮：中文 **Handoff 任务** / **Sessions 会话**；英文 **Handoff tasks** / **Sessions**。
- 建议 18pt semibold，主文字色，末尾向下 chevron；以实际 pt 设计，不照抄不同缩放截图的像素尺寸。
- 标题按钮高 34–36pt，长英文允许截断并提供完整辅助标签；红黄绿所在顶部工具行不改动。
- 标题下方常驻模式说明，不只在下拉菜单里解释。Handoff 模式显示“管理你的 Handoff 任务”，下一行引导“试试在 Agent 中说：‘总结当前 handoff task’”；Sessions 模式显示“继续你的 Claude Code / Codex CLI 会话”，下一行说明“按项目整理，点击继续上次对话”。
- 说明用 11–12pt secondaryText，提示可用 tertiaryText；按可用宽度自然换行、参与布局，不固定高度覆盖列表。保持标题、说明、列表三级视觉层次；说明文本不触发命令、不自动发送 prompt。
- Handoff 提示是自然语言引导，不是 CLI 内建命令；需在已绑定任务且 hooks 可用的现场验证写回流程，缺少配置时提供“配置 Agent hooks”入口，不保证未配置的 Agent 会自动写入任务。
- 点击弹出两行模式菜单，当前模式打勾，每项有简短副说明：“管理 Handoff 任务” / “继续本机 CLI 会话”。菜单不重复整段操作提示。
- 英文常驻说明：Handoff — “Manage your handoff tasks.” / “Try asking your agent: ‘Summarize the current handoff task.’”；Sessions — “Continue your Claude Code / Codex CLI sessions.” / “Organize by project. Click to pick up where you left off.”
- 优先复用 ShellMenuPopover 的视觉与键盘模式；若其不支持副标题，在共享菜单能力内做最小扩展，不为这个标题造另一套菜单系统。
- 搜索随模式变化：Handoff 搜索现有任务；Sessions 搜索会话标题、来源、项目、路径，不首期检索完整对话。建档按钮仅在 Handoff 模式显示；Sessions 不保留会误建任务的按钮。
- 每窗口独立保存模式、各模式查询、选择与滚动位置；新窗口继承最近选用模式，其他已开窗口不被同步切换。
- 模式切换仅替换内容区：保持面板尺寸、第一侧栏开合、第二侧栏开合、终端焦点策略不变，关闭旧模式的临时弹窗。

### 2.2 Sessions 布局

Sessions 侧栏不内嵌搜索框；筛选图标位于“最近会话”标题尾部，打开 lightty 自绘筛选与管理菜单（Agent、归档、更新时间或名称排序、刷新、原生恢复）。项目标题带垂直居中的 chevron，可整体展开或收起项目及其成员，不改变归组；标题尾部保留无边框 `⋯` / `＋`，更多操作尚未定义暂禁用，加号新建项目。项目行的打开/关闭文件夹使用配套 Lucide 矢量图标，其余系统图标保留 SF Symbols。分区标题使用正常正文色，不显示整行 hover；“暂无项目”使用较小常规字重、次级色与缩进，表达状态而非分类。底部状态区保持固定高度，没有下一页时隐藏加载更多。

顶部搜索及搜索快捷入口按第一侧栏模式路由：Handoff 搜索任务名称与交接正文；Sessions 独立浮层搜索已加载本机会话的标题、Agent、目录和 lightty 项目，包含本地归档记录。两者不共享查询状态；会话结果支持上下键、回车继续、Esc 和点击外部关闭，分页与错误提示沿用目录模块，不读取 Agent 对话正文。切换模式关闭现有搜索浮层。

Sessions 顶部的新建会话按钮提供 Codex / Claude Code 选择，使用设置中的对应启动命令，在新标签页的终端中执行；目录继承当前终端，缺省使用用户目录。不注入 Handoff 文档、不添加任务绑定，不把新建当成 resume。

“项目”和“最近会话”是同一个滚动列表中的平级分区，标题字号、颜色与左边距一致。会话可拖到具体的未归档项目行，使用原生落点提示，成功后展开目标项目；也可拖回“最近会话”标题、其下会话行或列表底部空白，统一高亮“最近会话”落点并解除项目归属。拖放与菜单共用组织模型的 move 操作，不写 Agent 历史。只接受当前侧栏列表发起的内部拖动；“项目”总标题、项目内会话行、同归属落点与搜索结果不执行移动。滚动条使用系统偏好的 overlay/始终显示样式及小号控件，不覆盖用户系统设置。标题箭头为小号 chevron.down，紧随文字居中，不使用文本符号。

最近会话行分为标题、Agent 与本地化时间、目录末级名三行；项目内使用紧凑两行，不重复父项目名；搜索结果补充归属信息。完整目录放在 tooltip，避免路径挤掉时间。第一、第二侧栏统一由滚动容器管理行 hover：只保留当前 hover 行的弱引用，滚动开始清除它，滚动期间只更新时间戳并忽略进入事件，停稳后命中测试一次。行不单独监听滚动通知；状态没变时不重绘。该等待仅控制 hover 恢复，不节流系统滚动事件。

两种模式共用 SidebarListScrollView：列表左缘距卡片 12pt、滚动容器右缘距卡片 2pt；内部右侧独立保留 16pt 滚动条区域，即使 overlay 隐藏也不改变行宽。正文和操作按钮始终在该区域左侧；Handoff 与 Sessions 使用一致的行首内边距、更多按钮和次级文字颜色。

```text
Sessions 会话 ▾
继续你的 Claude Code / Codex CLI 会话
按项目整理，点击继续上次对话
来源：全部 ▾                         搜索

项目                              ＋
▾ lightty                         ⋯
    修复侧栏裁切
    Codex · 20 分钟前
    打磨任务弹窗
    Claude Code · 昨天
▸ Breeze                          ⋯

最近会话
  一次临时排查
  Codex · 今天 · ~/scratch
```

项目是可折叠父行，会话是叶子。展开只影响列表，不打开终端；缩进与第二侧栏的树保持一致。
“最近会话”仅展示未归入任何项目的会话，避免同一条记录在项目和最近列表重复；搜索则平铺命中并显示项目名，不要求用户逐个展开。
项目下按最近更新时间排序；缺少更新时间的记录稳定落后，不因刷新随机抖动。项目手动顺序、折叠态单独保存。

会话标题用来源提供的名称 / 摘要，缺失时显示“未命名会话”及短 ID；控制字符清理、长度限制、纯文本显示。
副行显示 Agent 与时间；项目外额外显示目录，完整目录与 ID 可在详情中查看。磁盘变动时间不作为运行中状态。

### 2.3 单击与目的地

1. 已打开且可定位：前往对应窗口 / 标签页 / 终端；多个位置时显示已有的目的地列表。
2. 未打开：单击直接在**新标签页的新终端**运行原生 resume，不再弹一次“是否继续”。行菜单提供“在当前标签页分屏中继续”“在新窗口中继续”。
3. 发出恢复命令不等于成功：收到匹配 Agent 和会话 ID 的 hook 后才确认。未确认时再次点击，提示查看此前终端、明确重试或取消；不将 shell 仍运行视作 Agent 已恢复。SessionEnd、其他会话状态或终端退出后不复用该请求。
4. CLI 不存在、目录丢失、来源不可用：先显示可恢复的错误，不创建一个无声失败的空终端。目录丢失可让用户选择新目录并展示影响，不直接退到 home 后执行 Agent。
5. 已确认运行的 Codex 会话始终前往原终端，避免第二个 writer。手动恢复在后台进行最长约 2 秒的只读文件占用检查，同一身份的检查合并；对应 Agent 进程以可写方式持有相同来源目录下的准确会话文件时，提示回原终端继续或自行退出后再恢复，不创建新终端。没有匹配、工具失败或超时都属于未知，由原生 CLI 判断；进程名为 node 等情况及未持续持有文件的 Claude 会话可能无法识别。该检查不是互斥锁，不保证消除检查与启动间的竞态，不结束 Agent 进程、删除锁或自动 fork。原生选择器尚未选定会话 ID，其占用检查由 CLI 自行处理。

恢复环境由 `SessionConfigurationLocation` 保存来源语义：默认配置与显式目录分开，即使目录路径相同也不合并。默认配置通过子进程 `env -u` 清除对应覆盖变量，自定义配置只在子进程中设置该变量。侧栏、搜索、原生选择器与目录会话的工作区恢复共用 `SessionResumePlan`；工作区同时保存确认后的会话身份和配置来源，缺少来源时不猜测目录。恢复流程不修改 Agent 配置、认证文件或原始会话，不附加新建 Agent 的权限参数。

浏览历史和手动恢复不要求历史会话仍 alive。现有 `AgentResume.command(...alive:)` 的 alive 是“重启应用时是否自动重开 Agent”的策略，不能拿它过滤会话目录。

## 3. Project：lightty 的组织信息

项目是 lightty 内部的手动会话分组，与文件夹、工作目录及 Agent 的历史存储目录无关。

- 项目支持创建、改名、排序、展开/收起和移除；项目行仅切换成员可见性，保留 hover，不呈现持续选中态。
- 用户通过拖放或菜单收录 Claude 与 Codex 会话，每个会话最多属于一个项目；未指定归属的会话进入最近会话。
- 项目同名不合并，以稳定 ProjectID 区分；不根据 cwd、Git 仓库或目录规则自动分组。
- 移回最近会话解除归属；移除项目只删除 lightty 的分组信息，不删除会话或工作目录。
- cwd 仅用于显示和恢复终端，缺失或变化不影响已有分组，恢复时单独处理工作目录选择。

使用版本化 `~/.lightty/organization.json` 保存项目与手动归属；发布后的启动升级遵循 [持久化契约](../persistence.md)，正常写入原子替换，失败保留旧数据并告知用户。
一个 app 级持有者负责写入，窗口只发操作，避免多窗口覆盖彼此修改。缓存若落盘与此文件分开，缓存损坏允许重建，用户分组不能静默丢弃。

## 4. 来源能力与技术选择

官方事实、字段和具体链接见[调研文件](session-provider-research.md)，这里记录选择与代价。

| 路径 | 价值 | 代价 / 选择 |
| --- | --- | --- |
| Codex app-server `thread/list` | 结构化、分页、来源和归档过滤 | 优先；原生 Swift 可通过受管子进程 stdio 访问，必须做版本/能力探测 |
| Claude 官方 Agent SDK 列表 | 跨项目发现、官方维护读取逻辑 | 已接入固定 SDK 0.3.263 + Node 22 helper；最终分发与签名是发布门槛 |
| 直接读取私有 JSONL / SQLite | 无额外语言运行时 | 不作默认；格式漂移、索引缺漏、写入竞争全部变成本项目责任 |
| 原生 picker | 升级不兼容时仍能使用 | 降级入口，不冒充 lightty 已能列出全部记录 |

这里的 app-server 是本机 `codex app-server` 子命令，不是 ChatGPT App 或云端历史接口。只用于查询相同 CODEX_HOME 下的 CLI 会话目录，不通过 `thread/resume` 抢先加载历史或开始 turn；用户点击后仍由终端中的 `codex resume <id>` 执行。
它是外部程序，启动可能加载配置、初始化索引或产生内部文件；“只查询”不等于进程零副作用。能力 spike 必须验证认证、hooks/MCP 初始化、锁竞争和退出行为。

Claude SDK bridge 仅暴露元数据查询，不调用模型，不自动 npm/pip install，不要求用户为了看列表配置另一套 API key。
依赖由 `scripts/prepare-claude-helper.mjs` 在构建时准备；`package-lock.json` 固定 SDK 与依赖，Node archive SHA-256 固定运行时。debug 放在 `.build/claude-session-helper`，打包复制所需 SDK/运行时并分别签名。缺失时给出可操作错误并保留原生 picker，不回退到私有解析器或用户 PATH 中的 Node。

“官方 Interface”不代表永远不变。锁定 SDK 版本、记录验证过的 CLI 版本；未知字段忽略，必需字段缺失按来源失败，未知来源类型不得错误映射为可恢复的 CLI 主会话。

## 5. Module 设计：按变化来源划分

不要把 Sessions 条件分支塞进现有 `TaskSidebar.reload()` / `RestoreFlow` / `TerminalWindowController`。
以下是目标职责，不要求一次建立所有类或一类一文件。

```text
PrimarySidebar（外壳 / 模式 / 工具行）
  ├─ HandoffSidebarContent → 现有 TaskStore + Handoff 启动流程
  └─ SessionsSidebarContent → SessionLibrary
                                ├─ Claude Adapter
                                ├─ Codex Adapter
                                └─ 项目归组与用户组织信息

两种内容的用户意图 → TerminalLaunchCoordinator
                         ├─ 启动计划（新 Agent / resume / 仅终端）
                         └─ 现有新标签页 / 分屏 / 新窗口通路

第二侧栏 → 现有窗口标签页 / pane 树（不依赖会话文件格式）
```

### 5.1 核心值与 Interface

- `AgentKind`：Claude / Codex。`terminalOnly` 是启动选项，不是一种会话来源。
- `SessionKey`：`sourceID + agentKind + nativeSessionID`。sourceID 指向稳定的配置来源，不能只用裸 ID，也不能只用标题或 cwd。
- Codex 的 nativeSessionID 必须取具体 `thread.id`，不可误用新版 schema 中共享会话树的 `sessionId`；Claude 的毫秒时间与 Codex 的秒时间在 Adapter 内统一成 Date。
- `SessionSummary`：key、title、cwd?、updatedAt?、sourceKind、archiveState、availability。只包含列表需要的数据，不携带 transcript 全文。
- `Project`：稳定 ID、名称、折叠状态；手动归属是单独的用户组织记录。
- `LaunchIntent`：启动 Handoff 任务 / 恢复会话 / 仅开终端；`LaunchDestination`：当前标签页分屏 / 新标签页 / 新窗口，替换现有数字索引约定。

`SessionLibrary` 的外部 Interface 保持小：获取查询快照流、刷新、修改项目组织。它隐藏多源合并、排序、去重、部分失败、缓存以及请求取消。
查询结果必须同时含数据和各来源状态，不能因 Claude 出错而清空已成功读取的 Codex 会话。

来源 seam 内部只要求两件事：读取某查询的一页元数据；为确定会话生成可验证的 resume 计划。
Claude 与 Codex 是两个真实 Adapter，因此这里的协议有实际用途；不预建插件注册平台、事件总线或通用数据库层。
分页 cursor 是 Adapter 私有 opaque token，不能让 view 处理 Codex cursor 或 Claude offset。
Codex 按已验证版本显式配置 CLI sourceKinds，不把“没有 cwd 过滤”当成“所有来源”；桌面端、IDE、exec、子 Agent 不属于首期范围。
Claude 列表 SDK 会读取 transcript 头尾来生成元数据，limit 也不保证底层扫描量有界；性能预算需要测实际扫描，不能只看返回条数。

归组、排序、会话 key 和启动计划是 Foundation 纯逻辑；放入 LighttyCore 或独立无 AppKit 文件。
视图只处理展示与用户意图，@MainActor 更新 UI；磁盘枚举/外部进程在后台执行，依赖由组合入口注入，避免继续扩展全局 AppState 单例访问。

### 5.2 深度与避免过度抽象

SessionLibrary 是 deep module：小 Interface 隐藏多来源和刷新一致性；删除它会把这些复杂度重新摊给多个视图。
TerminalLaunchCoordinator 只在 Handoff 与 Sessions 两个调用方都落地时抽取：统一目录验证、计划、目的地及重复请求处理，不另包一层仅转发 addTab 的类。
任务与会话可以共用行外观、菜单和启动目的地控件；不要用一个充满可选字段的通用 Entry 模型吞掉两者不同语义。

### 5.3 原生启动与安全

- Agent 的来源、配置根、可执行文件与 resume ID 必须一致；从自定义 CODEX_HOME / CLAUDE_CONFIG_DIR 发现的会话，也在相同环境恢复。
- 新建 Handoff 已配置的 `codex --yolo` / `claude --permission-mode bypassPermissions` 保留，不在本轮改变。
- 建议 resume 默认沿用当前 `AgentResume` 的原生命令行为，不自动追加新任务的 bypass 参数。CLI 最终权限仍由其配置决定；若要统一成“恢复也跳过确认”，另设明确可见策略，经确认后实施。
- 现有用户自定义命令是任意 shell 文本，不能直接在末尾拼接 `resume`。新增结构化 resume 配置（可执行文件、参数列表、环境）与新任务原始命令并存；默认直接用官方 CLI。
- 受管查询进程用 executable + argv，不经过 shell。终端必须经 shell 首段输入时，在唯一编码出口处理逐参数 quoting / 控制字符拒绝，包含 ID、路径、环境；不插入会话标题或预览正文。
- 已有 AgentResume ID 白名单仍允许以 `-` 开头的文本，未来计划生成必须拒绝 option-like ID，优先验证官方 ID 格式，避免把数据解释成选项。
- Sessions 恢复不自动绑定 handoff、不注入新的交接文档。历史任务关联可后续作为显式入口，不能把恢复原对话悄悄改成开启新任务。
- 创建前预检，创建后使用 launch token 跟踪。有 hook 时以相同来源会话身份确认；无 hook 只标“已发起”，不能把“命令已发送”宣称“Agent 已恢复成功”。进程失败需保留可见终端错误。

## 6. 当前模块职责

| 文件 / Module | 职责 | 边界 |
| --- | --- | --- |
| `PrimarySidebar.swift` / `HandoffSidebarContent.swift` | 稳定外壳、模式切换 / TaskStore 展示、拖排、菜单 | 内容独立，不扫描 CLI 历史 |
| `TerminalWindowController.swift` | 两侧栏布局、动画、全屏避让、终端容器 | 只持有 PrimarySidebar 并接用户意图，不扫描会话、不保存项目规则 |
| `RestoreFlow.swift` | Handoff 摘要、Agent 选择、目的地 | 弹窗和搜索共用；不加入会话解析 |
| `AgentLaunchPreference.swift` | 新 Agent 命令及用户选择 | 保留配置兼容；与来源身份、resume 策略分开 |
| `WorkspaceSnapshot.swift` / `AgentResume` | 工作区恢复与原生 resume | 工作区快照使用 workspace.json；格式升级集中在启动迁移 Module，业务只读取当前模型 |
| `PaneStatusStore` / `PaneView` | hook 会话 ID、现场状态 | 给出已知 lightty 现场映射；来源标识缺失时不得猜测跨配置根相同 ID |
| `TaskFile.sessions` | Handoff 的历史会话关联 | 保持不变，不作为全量会话目录，不为新来源身份直接破坏任务格式 |

第一侧栏模式写入窗口快照时新增可选字段，旧快照缺失按 Handoff 解码；不要仅增加一个必填 Codable 字段导致所有旧快照失效。
现有 `taskPanelOpen` 等序列化键不急于改名；内部变量可逐步更名，避免概念更正变成无关大重构。

## 7. 刷新、规模与故障

- 进入 Sessions 模式或重新打开其第一侧栏时刷新；应用回前台、项目展开/收起、本地筛选与归组不触发目录查询。搜索浮层复用现有目录，仅未加载时读取；并发打开复用 app 级库正在进行的请求。手动刷新与加载更多保持可用。
- 刷新期间保留已加载行；加载仅显示为“最近会话”文字右侧的小型旋转指示器（搜索浮层放在搜索框尾部），不在主体或底部显示加载文字。空状态及错误摘要留在固定高度的底部状态区，长摘要提供完整 tooltip 与辅助功能文本。
- 项目分区及具体项目折叠使用稳定行 ID 的增量更新，保留无关会话行实例；保存状态变化不重建全表。用户折叠使用 220ms 行增删过渡，分区箭头围绕独立图层中心旋转，连续操作从当前呈现角度反向；系统“减少动态效果”开启时取消过渡。目录分批返回只做无动画增量更新。
- 列表虚拟化，稳定 key 差量更新；保留滚动锚点与选择，不在每次 reload 强制选第一行。
- 每来源独立分页，按更新时间进行全局合并；只有取到各来源足够的头部数据后才承诺全局顺序。未加载完明确显示加载状态，不以第一页假装“全部”。
- 首期标题/项目搜索覆盖已构建元数据索引；索引未完成显示“仍在加载”，不能把未扫描当无匹配。禁止每个按键重新拉全量 transcript。
- 外部进程具有超时、输出上限、退出清理和有限重试；切模式/新查询取消旧请求，用 generation 防旧结果覆盖新筛选。
- watcher 若后续加入，仅作为失效提示，不直接在回调读整库；合并事件，退出进程时取消资源。
- 缓存条目标为 stale，不把来源失联等同于会话被删。只有成功完整刷新后才清理不存在记录，项目手动归属仍保留可恢复引用。
- 日志只记来源、计数、耗时、错误类型，不落正文、完整 prompt、密钥或默认完整路径。

## 8. 实施计划与验收门槛

### P0：来源兼容性 spike（先做，决定分发路线）

产物：固定版本的合成会话 fixtures、能力矩阵、最小列表/命令构造验证，不接 UI。
验证 Codex initialize → thread/list 分页/来源/归档、进程副作用和退出；Claude SDK bridge 的跨目录结果与打包运行时。
针对两个工具都验证指定 ID + 原目录 resume，测试真实恢复须人工创建专用测试会话，不向用户历史对话发送试验消息。
通过标准：两来源的可列范围与降级方式明确；Claude 无开发环境分发有可执行结论；元数据读取不触发模型调用。
未通过则报告具体来源不可用，不开始编写大规模私有格式解析器。

### P1：第一侧栏外壳与命名

实现大标题、下拉菜单、每窗口模式状态，提取现有 Handoff 内容；Sessions 暂用明确的开发占位，不向正式用户宣称可用。
验收：任务拖排/搜索/启动完全回归，两栏独立开合与全屏无位移；切模式不改变终端树，旧快照正常恢复。

### P2：会话目录与默认恢复

实现两个 Adapter、SessionLibrary、元数据列表/过滤/刷新及原生恢复；统一三种启动目的地，Agent 类型不可跨会话切换。
验收：跨目录分页、单来源失败、CLI 缺失、目录丢失、无 hooks、连点去重、已打开前往；旧自动恢复仍尊重 alive，手动恢复允许已结束会话。

### P3：项目收拢

实现项目创建/改名/折叠、手动移动、最近会话和本地原子持久化；项目是本需求交付的一部分，不止做两种平铺列表就宣布完成。
验收：多 Agent 同项目、嵌套路径、worktree、多窗口同时操作、显式移出、删除项目不删除会话、重启恢复组织信息。

### P4：发布加固

合成 1 万条会话测试：主线程不做 I/O，缓存首屏目标 200ms 内（目标值，尚未实测），分页/筛选可取消，内存随元数据而非全文大小增长。
真实 UI 覆盖深浅色、全局 accent、键盘/VoiceOver、不同语言、长标题、快速切模式以及 macOS 13–15 / 26；旧系统抖动必须真机或对应系统环境验收，不能用 26 上通过代替。
发布包验证签名、helper 分发、无 Node/Python 开发环境、两 CLI 版本升级、外部程序不可用时降级。

每阶段独立提交，先验证 Interface 再做 UI 联调；没有源可用时不影响 Handoff 模式。功能开关只用于渐进上线，不长期保留两套侧栏实现。

## 9. 不在首期

对话全文阅读器、跨 Agent 转换历史、云端同步、会话删除/改名/归档写回、后台自动恢复所有会话、多层项目树、自动合并 worktree、任意第三方 Agent 插件系统。

Claude SDK helper 路线已选定，正式发布仍受签名、公证、许可及目标系统验收门槛约束。当前 resume 不追加 bypass；若修改此权限策略，需另行明确确认。
