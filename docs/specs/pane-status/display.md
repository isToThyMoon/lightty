# 展示与线程

> 状态：现行契约。（核对于 2026-10-29）

状态在主线程的发布、头部与侧栏展示、系统通知与动效。属于 [Pane 状态与 Handoff 注入契约](../pane-status.md)；状态含义见 [状态机](state-machine.md)。

PaneStatusStore 在主线程使用，接收队列回到主线程后发布定向 lighttyPaneStatusDidChange；不复用会重建任务列表的通知。
终端头部、第二侧栏和菜单栏使用一致的状态语义；高频更新原地重绘，不改变终端名称布局。提醒与通知由各自展示逻辑处理。
系统通知一个 pane 最多一条：同一 pane 再次完成替换通知中心里的旧那条，不堆叠；跌出未读
（用户读了、或被新的生命周期事件顶掉）与 pane 关闭时撤回。投递前重新核对仍未读、且仍不在眼前。
Agent 自己经 OSC 9/777 发出的桌面通知：与同一 pane 新产生的完成或介入状态落在同一个短缓冲窗口内时，
其文字成为 lightty 通知的正文（Codex 默认在回合结束与请求批准时即刻发出）。没配上的，若 hook 已认出该 pane
的 agent 则丢弃——状态提醒已覆盖同一件事，而 Claude 的权限提醒在对话框挂 6 秒后才发、空闲提醒要等 60 秒；
没有 agent 的普通 shell 照原语义投递。
lightty 通知的三格：标题为状态，绑定任务时后接「· 任务名」；副标题为 pane 头上的名字（会话名或 pane 名，
与任务名相同时省略）；正文只放配对到的 Agent 原话，没有就空。
会话名未定时（Claude 没有自定义名与 AI 标题，拿「最近一条提示」当名字，这条记录在回合结束后才落盘），
提醒先压住，等目录重读带回不同的名字即发，最多约 3 秒；名字已定的会话不等。
动态颜色的 CGColor 快照在外观变化时重新解析；不可见终端不应持续运行动画。
第二侧栏行底色只表达选中/悬停，不表达完成未读。完成以圆点和“✓ 已完成”文字提示；
完成文字用完成强调色，“需要你”用橙色且不加前置符号；两者均为 11.5pt semibold，其他状态
保持 10.5pt medium。未读文字使用原生 NSTextField + NSAnimation 做 3.2 秒一周期的颜色呼吸，
最弱阶段保留 80% 状态强调色；动画不改字号、透明度或几何。
隐藏、移出窗口或窗口不可见时停止；“减弱动态效果”开启时保留静态强调色。
状态圆点 7pt，终端头部与第二侧栏共用同一套呼吸（`StatusDotBreath`）：thinking / tool 两个
「还在跑」的状态做颜色呼吸，半程 1.5 / 1.0 秒，在状态色与掺 55% 身后表面色的弱化版之间往返
（侧栏混行底色，头部混终端背景色）；其余状态静止——持续动效只表示「在跑」，完成与等待靠
颜色、符号认出，头部另有落地时的一次性三拍脉冲。所有圆点接到同一个时钟上，相位一致：
各自起拍就是此起彼伏。不改透明度与几何：这个尺寸上透明度落在察觉阈值边缘，缩放会让一屏
行轮廓乱跳。thinking 与 tool 共用一个蓝，区分只靠呼吸节奏，状态色因此是四档
（灰 / 蓝 / 橙 / 品红）。
